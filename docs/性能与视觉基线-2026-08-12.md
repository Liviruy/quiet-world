## 2026-09-05 第八轮：导航按钮极致响应（用户要求：任何情况下切换按钮都不能卡）

即便上一轮禁了移动端的切换动画，ClientRouter 每次导航仍会执行 View Transition 的**整页截图**（新旧页面各一次）——移动端 GPU 叠加播放器的 backdrop-filter 模糊层，这一步本身就是卡顿源，禁动画禁不掉截图。修复：**移动端（<1024px）首帧前把 `document.startViewTransition` 替换为同步桩**——导航时直接换 DOM，完全跳过截图与动画管线，同时保留 ViewTransition 对象契约（updateCallbackDone/ready/finished/skipTransition）让 ClientRouter 正常工作。主题/配色的圆弧展开在移动端随之退化为即时切换（速度优先），桌面端全部动画原样保留。

配套：全局 `-webkit-tap-highlight-color: transparent`——移动端点击反馈只走控件自身的 scale/color 过渡（150ms），去掉浏览器灰色闪块。

### 实测（移动视口 390px）

- `__vtBypassed === true`，4 次连续导航全部走旁路（计数器确认），**切换耗时 94/85/91/98ms 稳定**（修复前 112/400/333/358 波动，含 300ms+ 卡顿）。
- 桌面 1440px：`__vtBypassed === false`，原生 View Transition 与全部动画不受影响。
- 功能回归：明暗切换、配色循环（meta 同步）、音乐跨页连续播放全部正常。
- `pnpm run build` 全链通过（astro check 0 错误、LQIP 完成），eslint 干净。

### 流程教训（再次强调）

后台运行的构建会**静默失败**（exit 0 但产物未更新，或 Node 偶发 0xC0000005 崩溃）——本轮又一次靠"检查 dist 内容是否包含新标记"才抓住。规则：**每轮修改后必须前台构建并核对 dist 文件内容，后台命令只用于长任务且结果必须二次验证**。另：日志断言不要匹配完整字符串 `[build] Complete!`（压缩日志带 ANSI 色码会匹配失败），用 `Complete` 子串或 exit code。

## 2026-09-05 缺陷修复：中文标题被预留挤断行 + 连续导航卡顿（用户报告）

1. **中文"清静世界"在 375px 屏幕换行**（上一轮英文遮挡修复的回归）：为图标行预留的固定 12rem 对中文场景过度——375px 下可用仅 ~122px < 标题 128px，断成"清静世/界"。修复：预留改为跟随图标行实际占位的响应式计算 `calc(100% - 7.25vw - 8rem)`（7.25vw 是与内容边距同步缩放的右侧偏移，8rem 是图标行宽），并对 <360px 的极窄屏把标题降一档字号（text-8 → text-6）。回归实测：中文 375/390 单行 32px、320 单行 24px；英文保持两行优雅换行；6 组合零重叠。**教训**：给悬浮元素预留空间时用响应式计算（含 vw 分量），不要拍固定值。
2. **连续导航卡顿难以响应**：每次切换页面都执行 View Transition 整页快照 + 交叉淡入，而右下角播放器是 `backdrop-filter: blur` 的固定层——移动端 GPU 在动画每帧反复重算模糊层，快速连续导航时明显掉帧、点击难以响应。修复：`transition.css` 对 **<1024px 移动端禁用 root 交叉淡入**（`::view-transition-old/new(root) { animation: none }`，直接切换）；命名组动画（配色/明暗的圆弧展开、站名 morph）保留，系统减弱动效时本就全禁。桌面端完整动画不变。
   - 修复过程中还发现选择器坑：`::view-transition-old(root):only-child` 永不匹配（root 的 old/new 快照恒有兄弟），初版规则是死代码，已改为直接禁用。
3. 验证：`astro check`/构建通过（注意：多行命令链中单步失败会被后续步骤掩盖，**必须以 dist 产物内容确认构建成功**——本轮再次靠检查 dist CSS 里的新规则抓到一次未生效构建）、eslint 干净、双语言三尺寸回归全绿。

## 2026-09-05 第六轮优化记录：导航零等待（用户反馈：首次进入点击其他页面很慢）

### 根因（实测确认）

预取策略为 `hover`/`tap`：桌面端悬停即预取有效，但**移动端没有悬停**——`tap` 在 pointerdown 才触发，等于点击瞬间才开始拉取页面。实测本地加载首页后零交互，无任何页面被预取；线上（artist.cc.cd，移动视口）首页 TTFB 524ms、完整加载 1.7s——每次点击都要硬等一个完整网络往返，弱网下 1-3 秒，正是用户感知的"弹出来很慢，要加载完成才起来"。

### 修复

1. **核心内容链接预取策略统一改为 `viewport`**（`PostList` / `PostNav` / `TagList` / `Navbar` / `Header` / `albums/index` 六处 + `astro.config.ts` 默认策略）：链接进入视口即在后台预取 HTML。实测移动端加载首页后**零交互 2.5s 内**已自动预取导航 4 页 + 全部可见文章；预取命中后点击实测 99ms 完成 URL 切换（对比线上无预取时的 500ms+ 往返）。桌面 Chromium 上 Astro 会将 viewport 预取升级为 Speculation Rules 预渲染，收益更大。预取按 IntersectionObserver 触发，只预取滚动到的链接，无全站请求风暴。
2. **音乐时长元数据延迟预取**（`MusicPlayer.astro`）：`audio.src` 的挂载从立即改为 `requestIdleCallback`（超时 4s 兜底），避免首次进入的关键几秒里 R2 往返与字体/CSS/内容抢带宽；时长仍会在进入后很快显示。

### 验证

- 加载首页零交互 → Network 中可见 posts/albums/photos/about 页面已被预取。
- 预取命中后点击导航实测 99ms 完成切换。
- `pnpm run build` 0 错误，eslint 干净。
- 提醒：本地频繁重建时 wrangler 需重启且浏览器 HTML 有 60s 缓存，测速请强制刷新。

## 2026-09-05 逻辑缺陷修复：移动端英文标题遮挡操作按钮（用户报告）

### 修复（`src/components/Header.astro` + `src/components/Button.astro`）

- 标题外层 wrapper 加 `max-lg:max-w-[calc(100%-12rem)]`（为图标行预留 192px）；链接加 `max-lg:ws-normal max-lg:break-words` 允许长英文名优雅换行（"Quiet World" 两行手写体），中文 4 字仍单行。**关键教训**：max-width 必须放在块级 wrapper 上——放在 inline-block 的 `<a>` 自身时 `100%` 以内容宽为基准，约束永远不生效（第一次修复即栽在这里，靠 DOM 实测才定位）。
